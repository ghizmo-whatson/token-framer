# token-framer — Image + Frame Mixer

Браузерный редактор токенов: загружает портрет и декоративную рамку, удаляет фон,
собирает композицию и позволяет показать отдельные части персонажа поверх рамки.
Рамка необязательна: можно обработать и сохранить только изображение.

Приложение написано на HTML, CSS и нативном JavaScript, без библиотек, сборки,
нейросетей и серверной обработки. Загруженные пользователем изображения
обрабатываются локально в Canvas и не отправляются в сеть. Интернет может
использоваться отдельно для галереи готовых рамок.

[Репозиторий на GitHub](https://github.com/atbakalov95/token-framer).
Язык интерфейса по умолчанию — русский; переключатель RU/ENG находится сверху справа.

## Запуск и файлы

Для работы нужны ровно **три файла в одной папке**:

| Файл | Назначение |
| --- | --- |
| [index.html](index.html) | Интерфейс трёх колонок, SVG-иконки, модальное окно пресетов и шаблон панелей умной очистки. |
| [main.css](main.css) | Стили, шахматный фон прозрачности, подсказки и адаптивная раскладка. |
| [main.js](main.js) | Вся логика редактора, обработка пикселей, локальный Worker и локализация. |

Откройте `index.html` в браузере. Установка пакетов, сборка и HTTP-сервер для
обработки собственных изображений не нужны. Соседние `main.js` и `main.css`
должны оставаться рядом с HTML-файлом.

Дополнительные каталоги — данные, а не файлы логики приложения:

- [ai_generated/](ai_generated/) — изображения пресетов и метаданные их категорий.
- `frame_references/` — локальные референсы; приложение их не загружает.
- `README.md` — документация.

Буфер обмена зависит от разрешений и возможностей браузера. Галерея пресетов
также зависит от доступности списка файлов и изображений: через `file://`
браузер может ограничивать локальные запросы, и тогда используется GitHub.
Для проверки локальной галереи можно запустить HTTP-сервер с индексом каталогов,
например из корня проекта:

```sh
python3 -m http.server 8000
```

Затем открыть `http://localhost:8000/`. Это необязательный способ запуска,
а не зависимость приложения.

Изображения и правки хранятся только в памяти текущей страницы. Перезагрузка
сбрасывает работу; перед ней сохраните нужные PNG. Формата сохранения проекта нет.

## Быстрый сценарий

1. Откройте портрет слева, рамку справа. Можно использовать файлы, перетаскивание,
   буфер обмена или галерею пресетов рамок.
2. Если фон нужно удалить, включите «Умное удаление фона» в нужной колонке.
   Выберите фон кликом или кнопкой поиска внутреннего/внешнего фона.
3. Проверьте подсветку либо предпросмотр прозрачности, настройте допуск цвета
   и нажмите «Применить». Панель останется открыта для следующей операции.
4. В центральном режиме «Смещение» переместите портрет и настройте масштаб токена.
5. Для выступающих частей включите режим «Маска» и нарисуйте, где персонаж должен
   появиться поверх рамки.
6. Сохраните готовую композицию центральной кнопкой «Скачать». Иконки PNG
   в боковых колонках сохраняют обработанные изображения по отдельности.

## Интерфейс и загрузка

При ширине окна больше 1200 px видны три колонки. При ширине 1200 px и меньше
они располагаются вертикально в порядке: изображение, результат, рамка.

| Колонка | Что находится внутри |
| --- | --- |
| Левая — изображение, в коде `token` | Загрузка, общий сброс и PNG изображения; ручные кисти; умное удаление фона; холст просмотра. |
| Центральная — результат | Режим «Смещение» / «Маска», масштаб холста и токена, кисть маски с её сбросом, предпросмотр и скачивание композиции. |
| Правая — рамка, в коде `frame` | Те же инструменты стороны, дополнительно пресеты и геометрическая защита кольцевой рамки. |

Вверху каждой боковой колонки две группы иконок:

- Загрузка: папка «Открыть файл», вставка из буфера; справа рядом с ними — «Пресеты».
- Действия: «Сбросить всю категорию» и «PNG изображения» / «PNG рамки».
  Экспорт доступен после загрузки, даже если панели кистей закрыты.

Пояснения к настройкам доступны при наведении и фокусе с клавиатуры. Плавающая
подсказка не обрезается границами прокручиваемой панели. `Esc` закрывает подсказку.

Загрузка поддерживает выбор файла и drag-and-drop в соответствующий холст.
Для буфера сначала нажмите его иконку на нужной стороне. Если прямое чтение
недоступно, приложение предложит нажать Cmd/Ctrl+V и запомнит сторону вставки.
Прямое чтение также поддерживает текст, начинающийся с `data:image/`.

**Загрузка нового изображения на любую сторону** сбрасывает правки этой стороны
и её зум/перемещение просмотра. Также сбрасываются смещение портрета в композиции
и центральная маска выступающих частей. Проценты масштаба сохраняются.

## Ручные кисти

Чекбоксы «Кисть удаления на токене» и «Кисть удаления на рамке» раскрывают
соответствующие инструменты. Три режима используют отдельные маски:

| Режим | Действие |
| --- | --- |
| «Удаление цвета» | Берёт RGB-цвета под основной кистью и удаляет все точные совпадения по всему изображению этой стороны. Допуска похожих оттенков здесь нет. |
| «Локальная очистка цвета» | Берёт образцы под красной кистью и удаляет совпадающие цвета только внутри основной фиолетовой кисти вдоль штриха. |
| «Ластик» | Стирает область обычным штрихом с круглой кистью. |

ЛКМ добавляет удаление, ПКМ убирает маску активного ручного режима. Другие
ручные маски и применённая умная очистка при этом сохраняются, поэтому ПКМ
не является общей отменой всех правок.

Основная кисть: 5–120 px, по умолчанию 30. Красная кисть локального режима:
3–120 px, по умолчанию 15. Размеры заданы в пикселях исходного изображения;
круги на холсте учитывают масштаб просмотра.

Ручная кисть и умная очистка одной стороны взаимно выключаются. Включение
ручной кисти отменяет неприменённый умный предпросмотр этой стороны.
Инструмент другой стороны продолжает работать независимо.

## Умное удаление фона

Инструмент доступен с обеих сторон после загрузки изображения. Его чекбокс
открывает панель и начинает независимый сеанс предпросмотра.

Порядок элементов панели:

1. Описание управления.
2. Две выпадашки: анализ изображения/рамки и область удаления.
3. Группа иконок: «Найти внешний фон», «Найти внутренний фон», «Сбросить точки».
4. Ползунок «Допуск цвета».
5. «Дополнительно»: остальные ползунки и флажки, восстановление настроек.
6. Выпадашка «Предпросмотр», статус и, при необходимости, подтверждение опасного выделения.
7. «Применить» и «Сбросить всю категорию».

### Выбор области

Справа доступны области «Внутри рамки» и «Снаружи рамки»; по умолчанию — внутренняя.
Слева — «Область по клику» и «Внешний фон»; по умолчанию — внешний фон.

- ЛКМ на фоне заменяет выделение одной стартовой точкой.
- Shift + ЛКМ добавляет точку, включая независимые участки. Максимум — 32 точки.
- ПКМ удаляет ближайшую пользовательскую точку.
- «Найти внешний фон» переключает область на внешнюю и заменяет прежнее выделение
  автоматическими образцами похожих гладких участков вдоль границ изображения.
- «Найти внутренний фон» переключает область на внутреннюю и ставит одну точку
  в центр исходного изображения, как обычный клик. Это не распознавание объекта:
  если в центре портрета находится персонаж, выбирайте фон вручную.
- «Сбросить точки» убирает точки и автоматическое выделение, сохраняя применённые правки.

Смена области через выпадашку очищает текущее выделение. Автоматический внешний
поиск не считает каждый пиксель у края фоном: используются сходство цвета,
гладкость и карта границ. Его результат всё равно нужно проверить.

### Анализ и настройки

Слева «Авто: цвет и границы» осторожнее обрабатывает тёмный фон; справа
«Авто: цвет и форма» дополнительно пытается защитить форму тёмного кольца.
«Только цвет и границы» использует обычное связное выделение с заданным допуском.
«Форма кольца» явно запрашивает поиск внутреннего и внешнего контуров и доступна
только справа. Если геометрия ненадёжна, показывается предупреждение.

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| «Допуск цвета», 0–100 | 28 | Допустимое общее отличие от цвета фона возле точки. Увеличение помогает с оттенками и градиентами, но может захватывать похожие детали. |
| «Защита контуров», 0–100 | 65 | Ограничивает пересечение найденных границ. 0 отключает барьер Sobel; слишком высокая защита может оставить кайму. |
| «Смягчение края», 0–5 px | 1 | Создаёт мягкий переход в узкой полосе края, в пикселях оригинала. Большое значение может истончить мелкие детали. |
| «Локальный допуск», 0–100 | 24 | Ограничивает цветовой скачок между соседними пикселями при распространении выделения. |
| «Закрытие разрывов», 0–3 px | 1 | Соединяет небольшие разрывы карты контуров. 0 отключает операцию. |
| «Убрать цвет фона с края» | Включено | Корректирует RGB и alpha пограничных пикселей для уменьшения светлой, чёрной или цветной каймы. |
| «Сохранить мягкие тени» | Выключено | Пытается сохранять сероватые тени возле рамки на светлом фоне; может оставить немного фона. |
| «Дополнительная радиальная защита» | Выключено | Запасное ограничение внутренней области по лучам из точки клика, когда основной контур не найден. Только справа. |
| «Предпросмотр» | «Подсветка удаления» | Подсветка показывает удаляемую область; «Прозрачность» показывает будущий результат на шахматном фоне. |

Все ползунки, кроме допуска цвета, и все флажки обработки находятся в «Дополнительно».
Геометрическая защита кольца и предупреждения о проникновении через его контур
относятся к рамке справа; фон портрета может нормально включать центр и края холста.

### Предпросмотр, применение и восстановление настроек

Изменение параметров пересчитывает предпросмотр по снимку начала текущей операции.
Оно не меняет применённое изображение и не накапливает изменения поверх предыдущего
предпросмотра. Панель другой стороны и центральная композиция не получают эти
правки до применения.

«Применить» записывает результат в обработанную основу выбранной стороны.
Панель остаётся открытой, параметры сохраняются, точки и подсветка очищаются.
Следующая операция начинает работу с уже применённого результата. Повторное
применение без нового выделения недоступно. Ручные маски и настройки композиции сохраняются.

Снятие чекбокса отменяет текущий предпросмотр и закрывает панель, но сохраняет
предыдущие применения. `Esc` также отменяет открытые умные предпросмотры;
если сначала открыта подсказка, первое нажатие закрывает её.

Кнопка «Восстановить значения по умолчанию» находится в «Дополнительно».
Она возвращает параметры обработки, область удаления и вид предпросмотра
к начальным значениям этой стороны. Применённые пиксели и ручные маски сохраняются.
Если при этом меняется область удаления, точки сбрасываются; иначе прежние точки
используются для нового предпросмотра. Секция «Дополнительно» остаётся открытой.

### Защитные предупреждения

Применение требует дополнительной отметки «Я проверил выделение…», если:

- Внутреннее выделение рамки достигло границы изображения.
- Внешнее выделение рамки попало в центр.
- Выделено более 92% видимых пикселей изображения любой стороны.
- Запрошенный поиск формы рамки не дал надёжного контура.

Предупреждение о запасном радиальном поиске само по себе не требует отметки.
Если подходящих видимых пикселей нет, применение недоступно. Уже прозрачная область
может дать пояснение о существующей прозрачности; её скрытый RGB не следует
использовать как образец чёрного фона.

## Композиция и центральная маска

Для результата нужен портрет слева. Если загружена только рамка, её можно
экспортировать отдельно; центральная кнопка скачивания остаётся недоступной.

Портрет сохраняет пропорции и масштабируется так, чтобы покрыть **полные размеры
рамки**, затем умножается на выбранный масштаб токена. Это не подгонка по границам
найденного отверстия. В режиме «Смещение» ЛКМ двигает портрет относительно рамки.

В режиме «Маска» появляется кисть: ЛКМ показывает дополнительные части персонажа
поверх рамки, ПКМ стирает эту центральную маску. Размер — 5–120 px, начальное
значение 30, в координатах итогового холста.

**Переход из «Маска» в «Смещение» очищает центральную маску**, а также сбрасывает
зум и перемещение центрального просмотра. Если маску нужно сохранить, оставайтесь
в режиме «Маска» и используйте среднюю кнопку для перемещения просмотра.

Обе процентные настройки доступны от 50 до 200%, начальное значение — 100%:

| Настройка | Фактическое действие |
| --- | --- |
| «Масштаб» | Задаёт размеры итогового холста относительно исходной рамки, а без неё — относительно портрета. С рамкой значения выше 100% добавляют поля, ниже 100% обрезают края: сама рамка не уменьшается. Без рамки портрет вписывается в изменённый холст. |
| «Масштаб токена» | Дополнительно увеличивает или уменьшает портрет относительно базового размещения. |

При изменении размера холста центральная маска переносится с сохранением её
центра; её содержимое не масштабируется. Размеры результата округляются вниз
до целых пикселей, минимум — один пиксель по каждой стороне.

## Управление просмотром

| Область и инструмент | ЛКМ | ПКМ | Средняя кнопка | Колесо |
| --- | --- | --- | --- | --- |
| Боковой холст, кисти выключены | Перемещение просмотра | — | Перемещение просмотра | Зум 1×–8× |
| Боковой холст, ручная кисть | Удаление | Убрать маску активного ручного режима | Перемещение просмотра | Зум 1×–8× |
| Боковой холст, умная очистка | Точка выделения; Shift добавляет | Удалить ближайшую точку | Перемещение просмотра | Зум 1×–8× |
| Центр, «Смещение» | Двигать портрет в композиции | Может также начать сдвиг | Перемещение просмотра | — |
| Центр, «Маска» | Рисовать верхний слой персонажа | Стирать центральную маску | Перемещение просмотра | Зум 1×–8× |

Зум и перемещение просмотра не меняют разрешение экспорта. Для изменения
самой композиции используются смещение портрета и процентные настройки центра.
В режиме «Смещение» используйте ЛКМ: текущий обработчик ПКМ также может начать
сдвиг и вызвать стандартное контекстное меню браузера.

## Что сбрасывает «Сбросить всю категорию»

Одинаковая надпись относится к категории, в которой находится кнопка.
Пошаговой истории Undo/Redo нет.

| Расположение | Что сбрасывается | Что сохраняется |
| --- | --- | --- |
| Верхняя группа левой/правой колонки | Умная очистка, её предпросмотр и все три ручные маски этой стороны; для рамки — кэш найденного окна. Умная панель закрывается. | Другая сторона, параметры инструментов, позиция/масштабы портрета и центральная маска. |
| Панель обычной кисти | Три ручные маски этой стороны. | Применённая умная очистка и настройки композиции. |
| Панель умного удаления | Все применения умной очистки этой стороны и её текущий предпросмотр; панель остаётся открытой. | Ручные маски, параметры инструмента, другая сторона и композиция. |
| Центральная панель кисти | Только маска выступающих частей персонажа. | Изображения, их очистка, положение и масштабы. |

Восстановление настроек по умолчанию — отдельная операция: оно не сбрасывает
применённую обработку изображений.

## Экспорт PNG

| Кнопка | Имя файла | Содержимое и размер |
| --- | --- | --- |
| PNG изображения слева, рядом с общим сбросом | `token.png` | Портрет с применённой умной очисткой и ручными масками, в разрешении загруженного изображения. |
| PNG рамки справа, рядом с общим сбросом | `frame.png` | Рамка с применённой очисткой и ручными масками, в её исходном разрешении. |
| «Скачать» в центре | `mixed_image.png` | Готовая композиция в размерах центрального холста, с верхней маской персонажа, если активен режим «Маска». |

Экспорт использует PNG с настоящим alpha-каналом. Шахматный фон и подсветка
не записываются в файл. Неприменённый умный предпросмотр также не экспортируется.

Автоматическое отверстие рамки в центральной композиции не меняет её исходные
пиксели. Если белое окно видно прозрачным в центре, это ещё не означает, что
оно вырезано из `frame.png`: для отдельного PNG рамки удалите фон и примените очистку.

## Пресеты рамок

Иконка «Пресеты» справа открывает галерею. Сначала показываются категории,
затем рамки выбранной категории. Выбор рамки загружает её на правую сторону
и закрывает окно; действуют те же сбросы композиции, что при обычной загрузке рамки.

Кнопка «Назад» возвращает к категориям. `Esc` внутри категории сначала возвращает
назад, следующее нажатие закрывает окно. Окно также закрывается крестиком или
кликом по затемнению. Переключение RU/ENG обновляет подписи и описания открытой галереи.
В галерее указано, что пресеты сгенерированы нейросетью; сама обработка изображений
в редакторе нейросети не использует.

### Файлы категорий

Каждая папка первого уровня в `ai_generated/` — категория. Например,
[ai_generated/simple/meta.json](ai_generated/simple/meta.json) содержит её описание.
`meta.json` необязателен и поддерживает поля:

```json
{
  "order": 10,
  "name": { "ru": "Простые", "en": "Simple" },
  "description": {
    "ru": "Базовые минималистичные и однотонные рамки.",
    "en": "Basic minimalist and solid-color frames."
  }
}
```

`name` и `description` могут быть строками или словарями языков. Для словаря
используется текущий язык, затем RU, затем ENG. Без имени используется название
папки с упрощённым форматированием. Категории сортируются по числовому `order`
(по умолчанию 1000), затем по имени папки. Изображения непосредственно в корне
`ai_generated/` попадают в последнюю категорию «Без категории».

Поддерживаемые расширения пресетов: PNG, JPG, JPEG, WEBP, GIF, BMP, AVIF;
фактическое декодирование выполняет браузер. Изображение превращается в статический
Canvas, анимация не редактируется и не экспортируется.

Чтобы добавить рамку, положите изображение в нужную папку категории. Менять список
файлов в JavaScript не требуется. Для опубликованной галереи нужно также опубликовать
изображение и при необходимости `meta.json`.

### Обнаружение и загрузка

1. `listDir()` пытается прочитать HTML-индекс локального каталога через `fetch`.
2. Если индекс недоступен, используется GitHub Contents API. На GitHub Pages
   владелец и репозиторий определяются по адресу; в остальных случаях используется
   `PRESETS.fallbackRepo` — `atbakalov95/token-framer`, ветка `main`.
3. Метаданные и изображения загружаются сначала локально, затем при необходимости
   с `raw.githubusercontent.com`. Для изображения проверяется доступность пикселей
   Canvas; непригодный источник отбрасывается.

Список категорий и рамок кэшируется в памяти страницы. Для обновления списка
после добавления файлов перезагрузите страницу, предварительно сохранив результат.
Без индекса каталога и доступа к GitHub автоматическая галерея может быть недоступна;
свои изображения всё равно можно открывать через файл или перетаскивание.

## Устройство кода

В `main.js` четыре раздела, каждый в своей IIFE; это не ES-модули и не отдельные файлы.

| Раздел | Ответственность и доступный объект |
| --- | --- |
| `TOOLTIPS` | Плавающая подсказка и `EditorTooltips.set()`, объяснения при наведении и фокусе. |
| `BACKGROUND` | `SmartBackgroundRemoval`: подготовка изображения, выделение, обработка края, создание процессора и поиск замкнутой области окна. |
| `SMART_UI` | `SmartRemovalUI.create()`: экземпляры двух панелей, параметры, снимки предпросмотра, применение, сброс и восстановление настроек. |
| `EDITOR` | Закрытое состояние `state`, привязка DOM, контроллеры сторон, ручные кисти, композиция, загрузка, галерея, экспорт и общая локализация. |

Первые три объекта доступны через `globalThis`; внутреннее состояние редактора
глобально не экспортируется. `index.html` подключает только `main.js` через `defer`.
Все необходимые для старта стили и SVG находятся в трёх рабочих файлах.

### Состояние и композиция

- `state.sides.token` / `frame`: исходный `source`, обработанная основа `smartSource`,
  отдельные маски `color`, `local`, `eraser`, параметры ручной кисти и `viewport`.
- `state.sides.frame.assets`: `overlay`, `windowMask`, `hasWindow`.
- `state.center`: смещение портрета, `userMask`, последний `composed`, параметры
  просмотра и центральной кисти. Процентные масштабы находятся в общем `state`.

`composeEffectiveCanvas()` берёт `smartSource`, если он есть, иначе `source`,
и вычитает три ручные маски через `destination-out`. Оригинал остаётся доступным
для сброса. Применение умной очистки меняет основу относительно alpha снимка,
чтобы не вычитать уже существующие ручные маски второй раз.

`buildFrameAssets()` ищет окно среди прозрачных, почти белых и некоторых ярких
полупрозрачных пикселей возле центра. `findEnclosedRegion()` отвергает область,
дошедшую до границы холста. Из результата строятся маска окна и рамка с вырезанным
окном. Если ручной разрыв разрушил ранее найденное окно, при подходящем центре
сохраняется предыдущая маска тех же размеров. Новая рамка и общий сброс очищают кэш.

`composeFinalImage()` рисует портрет, обрезанный по окну и границам рамки,
затем рамку, затем дополнительный слой портрета по `userMask` в режиме «Маска».
Без рамки рисуется портрет, размещённый на итоговом холсте.

### Умное выделение

Ядро использует sRGB → XYZ D65 → LAB, медианный образец фона и его шум,
Gaussian 3×3 для анализа, Sobel по светлоте и цвету, адаптивный порог границ,
ограниченное морфологическое closing и 4-связный BFS с глобальным и локальным ΔE76.
Исходные пиксели не размываются ради обнаружения контуров.

`detectFrameStructure()` ищет согласованную кольцевую полосу по 720 направлениям
от центра изображения и ограничивает заливку внутренним либо внешним контуром.
Это помогает сохранить тёмный материал, близкий к чёрному фону. Дополнительный
`radialGuard()` использует 360 лучей из точки клика для защиты внутренней области.

Обработка края основана на карте расстояний и локальной модели смешивания цвета
фона с цветом объекта. В тёмных переходах используется кодированный RGB вместо
слишком сжатого линейного RGB; неустойчивая коррекция пропускается. Исходная
прозрачность учитывается, alpha не увеличивается.

Процессор создаёт локальный Worker из Blob, без отдельного worker-файла и загрузки
кода из сети. Если создать Worker не удалось, тот же алгоритм выполняется порциями
в основном потоке. LAB и градиенты кэшируются на время сеанса; изменение только
смягчения, ореола или теней повторяет обработку края, а переключение предпросмотра
не запускает новое выделение. Итоговая маска имеет исходное разрешение.

## Ограничения и проверка

- Сегментация не распознаёт персонажей и материалы. Совпадающие с фоном детали
  неоднозначны; возможна ручная доводка или другой режим анализа.
- Геометрия кольца предполагает преимущественно замкнутую рамку вокруг центра
  изображения с одним внутренним и внешним радиусом на направление. Сильное
  смещение, глубокие вогнутости и большие разрывы могут дать неверный контур.
- Различение мягкой тени и примеси фона эвристическое. Чёрную тень на чёрном фоне
  нельзя достоверно восстановить по этому изображению.
- Автоматическое окно композиции рассчитано прежде всего на прозрачный или светлый
  центр. Непрозрачный тёмный центр может потребовать внутренней умной очистки.
- Большие изображения требуют заметного объёма памяти. Фиксированной гарантии
  времени обработки и максимального разрешения в интерфейсе нет.
- Галерея и буфер обмена зависят от браузерных разрешений, происхождения страницы
  и доступности источников; обработка собственных файлов не требует сети.
- Пошаговых Undo/Redo, сохранения проекта и восстановления после перезагрузки нет.

В проекте нет сборщика, тестового раннера, отдельных тестовых файлов и автономной
HTML-копии. Для проверки синтаксиса при установленном Node.js достаточно:

```sh
node --check main.js
```

Ручная проверка после изменений:

1. Открыть `index.html`, загрузить портрет и рамку, проверить оба способа PNG-экспорта
   и центральное скачивание.
2. Проверить три ручные кисти, ПКМ, зум и перемещение каждого холста.
3. Проверить умную очистку с обеих сторон: точки, автоматический внешний поиск,
   центр, подсветку/прозрачность, предупреждения и несколько применений подряд.
4. Убедиться, что восстановление настроек не отменяет применённые пиксели,
   а каждый сброс действует только на свою категорию.
5. Проверить положение, масштабы, центральную маску и её очистку при переходе
   в «Смещение»; отдельно проверить окно рамки после ручного разрыва контура.
6. Проверить RU/ENG, подсказки при наведении и фокусе, галерею с категориями
   и загрузку своих файлов без интернета.
